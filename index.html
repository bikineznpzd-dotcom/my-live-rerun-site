Planned connection model

Authentication and streaming access are separate

The client is designed around official authorization flows and does not rely on private APIs, session extraction, license bypasses, or automated CAPTCHA solving. This integration remains conditional on Developer App configuration, an independently secured Auth Broker, platform permissions, and successful testing.

01

User starts connection

The desktop application can begin OAuth or QR authorization after Developer App settings are configured.

02

User grants consent

TikTok presents its own sign-in and consent experience for the scopes requested by the application.

03

Broker would handle tokens

A separately implemented server-side Auth Broker would be required to protect the Client Secret, access token, and refresh token. That server is not included in the current project.

04

Desktop shows permitted data

Basic account information can be displayed only after the user grants the required scope.

!
Real TikTok login and LIVE streaming are not verified.
Login Kit does not grant LIVE access. Signing in would not automatically provide a Stream Key or permission to start a LIVE. A user must separately have platform LIVE eligibility and an authorized RTMP/RTMPS destination.
